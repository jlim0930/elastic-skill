# Cross-Component — Security & Auth Sub-Agent

Scope: API key lifecycle across Fleet/Agent/Beats/APM, service token problems, role/privilege issues across components, 401/403 from multiple components simultaneously, ES security configuration affecting all components.

## Retrieval Protocol
Follow [../../../../shared/retrieval-protocol.md](../../../../shared/retrieval-protocol.md) strictly. KCS → Docs → Web.
Suggested KCS queries: `"Elastic Stack authentication multiple components"`, `"API key invalid Fleet Beats"`, `"Elasticsearch RBAC role all components"`, `"service token Fleet security"`, `"Elastic Agent 401 Elasticsearch"`.

## Diagnostic Steps

### 1. Auth Error Triage Across Components
```bash
# Elastic Agent
grep '"level":"error"' /opt/Elastic/Agent/data/elastic-agent-*/logs/elastic-agent-*.ndjson \
  | grep -E "401|403|unauthorized|forbidden|auth" | tail -10

# Filebeat
grep -E "401|403|unauthorized|forbidden" /var/log/filebeat/filebeat | tail -5

# APM Server
grep -E "401|403|unauthorized|forbidden" /var/log/apm-server/apm-server | tail -5

# Logstash
grep -E "401|403|unauthorized|forbidden" /var/log/logstash/logstash-plain.log | tail -5
```
If all components show 401/403 simultaneously → shared ES credential issue (user disabled, password changed, security config changed).

### 2. Elasticsearch Security Configuration
```bash
# Is security enabled?
curl -s http://localhost:9200/ | jq '.tagline'
curl -s http://localhost:9200/_security/authenticate -u <user>:<pass> | jq '.username'

# Check if auth is required
curl -s http://localhost:9200/_cluster/health | jq '.status // .error'
```
`missing authentication credentials` = security enabled but component isn't sending credentials.

### 3. Shared Credentials / API Keys
Each component uses different credentials:
| Component | Auth Method | ES Credential |
|-----------|-------------|---------------|
| Fleet Server | Service token | System-managed |
| Elastic Agent | API key (per agent) | Generated by Fleet Server |
| Filebeat/Beats | config username/password or API key | Configured in Beat output |
| APM Server | ES user or API key | Configured in APM output |
| Logstash | ES user or API key | Configured in Logstash output |

```bash
# Check API keys for Fleet agents
curl -s -u <user>:<pass> "http://localhost:9200/_security/api_key?name=fleet*" \
  | jq '[.api_keys[] | {name:.name, invalidated:.invalidated, expiration:.expiration}]' | head -10
```

### 4. Bulk API Key Invalidation
If all agents show 401 simultaneously:
```bash
# Check if Fleet agent API keys were bulk-invalidated
curl -s -u <user>:<pass> "http://localhost:9200/_security/api_key?invalidated=true&name=fleet*" \
  | jq '.api_keys | length'
```
Cause: ES security reindex, disaster recovery, or accidental bulk invalidation.
Resolution: re-enroll agents or use Fleet's "Force re-enrollment" feature.

### 5. Password Change Impact
If the ES `elastic` password was changed or user accounts were rotated:
```bash
# Update credentials in each component's config
grep -E "password|username" /etc/filebeat/filebeat.yml 2>/dev/null
grep -E "password|username" /etc/metricbeat/metricbeat.yml 2>/dev/null
grep -E "password|username" /etc/apm-server/apm-server.yml 2>/dev/null
```
After updating credentials: restart each component and test auth.

### 6. Role and Privilege Check
```bash
# Check role for a user
curl -s -u elastic:<pass> "http://localhost:9200/_security/user/<username>" \
  | jq '.["<username>"] | {roles:.roles}'

# Test specific privileges
curl -s -u <username>:<pass> -X POST "http://localhost:9200/_security/user/_has_privileges" \
  -H "Content-Type: application/json" \
  -d '{"cluster":["monitor"],"index":[{"names":["logs-*"],"privileges":["write","create_index"]}]}' \
  | jq '{cluster:.cluster, index:.index}'
```

### 7. ES Security Audit Log
```bash
grep -E "ACCESS_DENIED\|AUTHENTICATION_FAILED\|ANONYMOUS_ACCESS_DENIED" \
  /var/log/elasticsearch/elasticsearch_audit.json | tail -20
```
Provides the actual ES resource being denied for each component.

### 8. Keystore / Secret Management
For Beats using ES keystore:
```bash
filebeat keystore list -c /etc/filebeat/filebeat.yml
# Verify the password key matches what's in the config
grep "\${" /etc/filebeat/filebeat.yml | head -5
```

### 9. TLS + Auth Combined Issues
If both TLS and auth are failing: fix TLS first (auth can't succeed through a broken TLS connection).
Check order: TLS handshake → HTTP 401 check → data.

### 10. KCS + Docs Lookup
Execute retrieval protocol with the specific component, HTTP status code, and ES operation being denied.

## Token Budget
- Triage all components for 401/403 in one pass before any per-component deep dive.
- ES audit log gives ground truth for all auth failures.
- Max 3 KCS queries, max 3 retry attempts total.
